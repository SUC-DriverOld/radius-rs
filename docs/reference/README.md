# Reference data

Data kept for provenance and reproducibility. **Nothing here is compiled into the
crate** — no `src/` file reads this directory, and no build step touches it. Deleting
`docs/reference/` changes nothing about `radius.exe` or `radius_rs.dll`.

## `vc_schedule.bin`

The research corpus' per-granule vocoder schedule: the `rx_vc_sched[]` table from
`libradius/src/engine/vc_schedule.h`, packed row-major.

| property | value |
|---|---|
| layout | 28993 rows × 4 little-endian `i32`: `pos`, `cdel`, `f1`, `f2` |
| size | 463 888 bytes |
| provenance | `vc_schedule.h`, generated by `libradius/tools/rx_vc_schedule.py` v2 |
| source corpus | `<research-corpus>/optest2/cal_1p6_30s_v6/.../manifest.jsonl` (278 752 lines) |
| ratio | 1.4142135623730951 |
| missing values backfilled | 1 |
| Σ `cdel` | 1 396 493 (reconciles against a 1 393 598-frame input) |
| Σ Δ`pos` | 1 974 752 |

### Why it is not in `src/`

The engine never reads it. `vocoder_core.c` says so explicitly — "本文件不引用
vc_schedule.h / vc_sched_neg.h 的逐粒真值表" — and computes its schedule with
`rx_vc_calc_sched`, which the Rust port mirrors as
`radius_rs::vocoder::vc_calc_sched` (including the negative-semitone branch,
`ratio < 1` → `round(nominal·√2)`).

It is also **not usable as a parity oracle**: the table's step sizes differ from the
engine's own. The table advances 222/444 early and 155/311 late, while the engine
uses 264/373 at 48 kHz and 204/288 at 44.1 kHz. Comparing the two would test
nothing, which is why the schedule tests in `src/` were removed along with the
table rather than kept as a self-checking ritual.

What it *is* good for: it is the record of how the reverse-engineering work
recovered the scheduler, and the sums above are the fingerprint of that particular
corpus.

### Reading it

```python
import struct
rows = struct.unpack("<%di" % (28993 * 4), open("docs/reference/vc_schedule.bin", "rb").read())
pos  = rows[0::4]
cdel = rows[1::4]
f1   = rows[2::4]
f2   = rows[3::4]
assert sum(cdel) == 1396493
```

### Regenerating

`tools/archive_schedule.py` parses the header and packs this file, asserting the row
count, both column sums and monotonicity of `pos`:

```bash
python tools/archive_schedule.py            # rewrite the archive from the header
python tools/archive_schedule.py --check    # verify the archive against the header
```

Unlike the constant tables in `src/vocoder/table_data/`, this file is *derived from*
`libradius/`, so `--check` needs that directory to be present. The committed
`.bin` is the archive of record; if the sibling reference projects are ever removed,
this file is what remains of the scheduler corpus.
